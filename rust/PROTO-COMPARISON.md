# Етап 0: порівняння інтерфейсів для переписування Transly на Rust

Складено 2026-11-24 за прототипами `rust/proto-egui` і `rust/proto-slint` та поточною веб-збіркою (Tauri). Усі три показують те саме: таблиця на 100 000 рядків, оригінал із підкресленими термінами й номерами, поле перекладу, права панель із картками й коментарем.

## Виміри (Linux, Xvfb, програмний OpenGL — це песимістична оцінка; не порівнюйте їх із Windows із відеокартою)
| | Поточна веб-збірка | egui 0.31 | Slint 1.19 |
|---|---|---|---|
| Прокрутка таблиці 100 тис. рядків, мс/кадр | 17,6 середній, 33 p95 (стеля — 60 Гц) | ≈7 (кадр без обмеження), сам розрахунок ≈0,2 | 16,8 (перемальовування таймером) |
| Відкриття файлу на 100 тис. рядків | 0,47 с | миттєво (дані в пам'яті) | миттєво |
| Пам'ять | ≈73 МБ купа JS + процес вебвʼю | ≈129 МБ (RSS, з програмним GL) | ≈167 МБ (RSS, з програмним GL) |
| Розмір виконуваного файлу | інсталятор 2,5 МБ (вебвʼю системи) | 15 МБ | 27 МБ |

Висновок із цифр: поточна веб-збірка на 100 тис. рядків уже швидка (відкриває за 0,5 с, тримає частоту екрана). Швидкість — не причина переписувати; egui трохи швидший, Slint на рівні веба.

## Найважче місце: поле перекладу з позначками термінів
| | Веб | egui | Slint |
|---|---|---|---|
| Позначки всередині редагованого тексту (заливка + підкреслення кольором) | так | **так**: `TextEdit::layouter` + `LayoutJob` (фон, підкреслення, колір діапазону); номери-кружечки малюються за позицією з `Galley` | **ні**: `StyledText` лише для показу, лише підкреслення й колір тексту, без заливки; `TextEdit` стилізувати діапазонами не можна |
| Клік по слову оригіналу → вставка | так | так (`Galley::cursor_from_pos`) | потребує накладки з прозорого поля й власного обчислення позицій |
| Вигляд «з коробки» | власний CSS | базовий, потрібна своя тема | гарніший базовий вигляд, але стандартне поле — світле, тему переписувати |

## Інше
| | egui | Slint |
|---|---|---|
| Ліцензія | MIT/Apache-2.0 | GPL-3.0, «royalty-free» (з умовами й атрибуцією) або комерційна — потребує рішення власника |
| Стилізація | у коді (`Visuals`, `Frame`); токени теми переносяться вручну | декларативна `.slint`, ближча до CSS, але менше можливостей для нестандартних віджетів |
| Доступність | `accesskit` увімкнено; поля тексту і власні віджети слабкі | `accessibility` (accesskit) для стандартних віджетів; власні — вручну |
| Український ввід / IME | через winit; на Windows треба перевірити | через winit; на Windows треба перевірити |
| Тестування UI | `egui_kittest` (знімки, запити доступності) | тестовий бекенд `i-slint-backend-testing` |
| Шрифти | у стандартному наборі немає «➤» — потрібен свій шрифт | те саме, свій шрифт |

## Рекомендація
Продовжувати на **egui**, якщо перевірка на Windows (ввід українською, Narrator, швидка прокрутка) пройде: це єдиний із двох, у якому поле перекладу з позначками працює вже зараз. Slint виграє зовнішнім виглядом, але саме в центральному екрані потребує обхідних шляхів. Для перевірки на Windows: Actions → «Rust prototype» → `proto-latest` містить обидва `.exe`.

Що прототипи **не** перевіряють і лишається ризиком: доступність і IME на справжньому Windows, власна смуга вікна, вигляд високих DPI, обсяг роботи на ~25 тис. рядків логіки інтерфейсу.
